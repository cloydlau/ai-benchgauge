# AA 编程榜每任务成本

编程分类的 Artificial Analysis 榜单保留原能力分数和能力排名，在成绩下展示平均每任务 API 成本（美元）。支持 “分数从高到低” 和 “成本从低到高” 两种展示顺序；排序是本地临时状态，不重新采集榜单，也不覆盖国家、开放权重、搜索或来源选择。

## 数据口径

- 固定来源仍是 https://artificialanalysis.ai/agents/coding-agents 。服务端和 Apple 直接采集解析同一条 index 记录的 `mean.costUsd`，保存为可选的 `entry.taskCostUSD`。
- 不使用单个 eval 的成本、总运行费用 `sums.costUsd`、中位数、模型 token 报价或模型分数反推成本。缺失、负数、非数值和非有限值保持未知；零是有效价格。
- 这是按量 API 平均任务成本，包含来源适用的缓存写入、缓存折扣和输出计费，不是每个成功任务成本、订阅套餐折算价格或完整生产运维成本。必须同时查看成绩。
- 成本相同时按成绩从高到低，再按原能力名次排序。缺失成本排在最后；原排名、奖牌和排名变化继续表示能力榜位置，不能理解成成本名次。相对成绩的底色仍以筛选后最高成绩为基准。
- 公司仍按榜内最强型号排名，费用取该型号同一条记录的成本。最强型号未提供成本时显示未知，不借用更便宜兄弟型号或最低报价。
- 显示精度统一：零为 `$0`，小于 `$0.001` 为 `<$0.001`，小于 `$0.01` 保留三位小数，其余保留两位。缺失显示 `—`。

## 各端与离线/导出

共享快照通过 OSS、客户端缓存和 Windows Swift 引擎投影保留成本。兼容没有此字段的旧快照。成本变化推进 `contentUpdatedAt`，但不会制造能力名次升降；来源发布时间仍按原规则展示。

- macOS：编程导航区提供分数/成本菜单；原生表格成绩下显示成本，双行表头标出 `$/task` / `$/任务`。桌面复制图片使用同一视图和顺序。
- Windows：AA 编程成绩列的表头提供排序菜单；共享模型、真实 WPF 表格和同视图导出保留成本。
- iPhone / iPad：共用表头菜单和缓存的行投影；切换排序重新计算行但不请求数据，分页图片导出消费相同顺序和费用。
- 微信小程序：AA 编程表头切换排序；列表窗口化仍只传可见行，其他榜单不增加每行成本字段。Canvas 导出完整排序结果、原能力名次、成绩和成本，并明确美元/任务单位。

三语来源说明解释费用口径、公司取值、缺失值和排名含义。其他来源尚无这个任务成本字段，不参与本次排序。

## 验证与交付边界

`Scripts/coding-cost.test.mjs` 覆盖来源层级选择、零/缺失/畸形成本、排序不变异、公司最强型号费用、成本变化与内容时间/排名变化。小程序专项与真实控制器测试覆盖三语排序、成绩基准、公司视图、旧缓存、搜索和 Canvas 双值导出。Swift 和 Windows 共享回归覆盖解析、离线往返、排序、原能力排名与费用精度；iPhone/iPad 的投影回归同时检查分页导出数据。

共享 `Tests/fixtures/visual-state.json` 增加 AA 编程费用记录及三语、两种分组、两种排序场景，供真实 Mac / Windows 原生捕捉复用。包括零、缺失、小数费用、长名称及原能力名次变化。当前 Mac 的运行记录和前后截图放在忽略目录 `work/coding-cost/`。
