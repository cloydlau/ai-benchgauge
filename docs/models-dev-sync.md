# models.dev 自动补全

2026-10-19 接入共享服务。榜单仍以各榜原始来源为准；模型资料由服务端统一同步、验证并保存到私有 OSS，所有客户端复用同一份匹配结果。客户端不直接请求 models.dev。

## 来源与字段

固定来源为 [models.dev 完整 catalog](https://models.dev/catalog.json?type=all)，参见[官方数据结构说明](https://github.com/anomalyco/models.dev#api)。同时取得独立模型资料与供应商端点，避免把某家供应商的限制或报价当成模型自身的统一属性。

- `entry.modelMetadata`：canonical ID、名称、上下文/输入/输出 token 上限、开放权重、模型许可、发布日期、资料更新日期及供应商 `offers`。
- 每个 offer 保留供应商 ID/名称、端点模型 ID、端点 token 上限、状态及报价。报价单位为 USD / 百万 tokens，保留零价格、缓存读写、音频、推理和上下文分段价格；缺失价格保持缺失，不计算跨供应商最低价。
- token 上限为 0 时不作为可用的 token 窗口；价格 0 则是有效价格。
- `board.modelMetadataSource`：资料来源、URL、下载内容 SHA-256、同步时间及完整 MIT 许可。模型资料的同步时间独立于榜单的抓取/发布日期。
- `openWeights` 只表示权重是否公开，不能据此断言代码开源或允许商业使用。原始 `license` 字段单独保留。现有“源码”筛选按原有开放权重口径补全：上游明确分类优先，其次既有核实规则，最后才使用 models.dev。
- models.dev 不提供统一的榜单样本量。Arena 的 `voteCount` 继续来自官方榜单数据集；不把投票数当作训练样本数。

数据库采用 [MIT 许可](https://github.com/anomalyco/models.dev/blob/dev/LICENSE)。完整版权和许可声明随 OSS 快照及榜单资料来源返回，并在各端离线快照中保留。数据库的 MIT 许可不替代具体模型的许可。

各端来源说明标注“模型资料：models.dev”并链接至 https://models.dev。Mac 的许可证与声明、Windows 的第三方声明、手机/平板和小程序的第三方许可均包含完整 MIT 版权及许可文本，可离线读取，不依赖模型是否匹配或接口返回。小程序的独立上传暂存输入包含许可源文件，许可变更也参与更新检测。

## 同步与故障保留

部署脚本复用既有新加坡公共数据采集函数，增加经专用令牌认证的固定 `/v1/models-dev` 路由。该函数不持有 OSS 或云账号凭据，也不接受调用者传入任意下载 URL。

榜单成功更新并原子保存后，检查新增模型和关键资料缺口；没有缺口就直接复用目录。缺口包括无法确认模型身份、缺失开放权重分类或模型许可，以及文本模型缺失上下文窗口或完整输入/输出报价。窗口可由 canonical 资料或明确关联的供应商提供；0 价格和 false 开放权重均为有效值。图片、视频榜不因缺少 token 窗口或 token 报价触发补全。发布日期、样本量和其他可选字段不作为必填条件。

缺口指纹按模型身份和缺失项计算，与排名、分数、榜单时间和条目顺序无关，写入 `benchgauge/models-dev/requests/coordination.log`。`models-dev-fill` 认证任务每分钟检查一次队列：没有待处理项时不读取完整目录，也不请求上游；有缺口时允许在二十四小时周期内提前采集。这样目录下载不占用榜单刷新或客户端贡献资格的执行时间。全局十五分钟限频仍然生效，因此刚进行过采集时，新缺口会等待剩余冷却时间。并发更新通过追加位置校验合并，下载过程中出现的不同缺口留待下一轮处理。

采集成功后，同一榜单的相同缺口暂缓六小时再触发，避免上游尚未收录时反复请求；新增的不同缺口可以单独排队。失败保留待处理项，由每分钟任务在十五分钟冷却结束后重试。调度存储失败不将已经保存的榜单变成刷新失败，每日检查仍可更新全目录。

`models-dev-sync` 定时触发器使用 UTC Cron `0 0 0 * * *`，每天北京时间 08:00 检查已有模型价格、上下文、许可等变化，未满二十四小时且无待补全项时复用最近成功检查结果。缺口的六小时负缓存独立于这个检查周期。两种原生 FC 事件均通过 `/invoke` 处理，要求独立同步令牌；令牌只在本地忽略文件、函数环境变量和定时触发器配置中保存，不进入部署包、客户端或日志。

OSS 对象为 `benchgauge/models-dev/latest.json`，协调日志为 `benchgauge/models-dev/coordination.log`。追加位置校验确保并发实例只有一个下载者；失败尝试至少间隔十五分钟。成功检查时间独立记在协调日志的 `checkedAt`；快照的 `fetchedAt` 继续表示当前已发布内容的采集时间。普通 GET、缓存刷新和刷新授权不排队；只有真正保存的新榜单检查缺口。

当前 API 每次采集仍下载完整目录。校验后按模型 ID 比较资料、按供应商及端点 ID 比较报价，忽略 JSON 对象键顺序、模型/供应商端点排列、原始响应哈希及采集时间差异；其他公开数组的顺序保留。内容不变时不重写 `latest.json`，保留原始修订和采集时间，只记录成功检查。内容变化时复用未变模型记录，将新增、变化或删除后的完整有效快照一次原子发布；不是按字段向 OSS 发多个写请求，也不会用旧字段掩盖上游已删除的事实。

下载限制 12 MiB；新加坡返回的规范化快照限制 8 MiB。校验结构、身份、布尔值、数值范围、token 整数、许可、模型与供应商数量、唯一 ID 和时间。模型数跌至前一有效快照的 80% 以下时拒绝发布。只有完整验证通过才原子替换 OSS 对象；上游、存储或校验失败均保留上一份有效快照。进程内仅作短时缓存，冷启动仍读 OSS。

## 匹配边界与客户端

优先匹配 canonical ID 或上游明确关联的供应商端点 ID；其余仅接受规范化后唯一的模型名、canonical 名称或已明确关联的端点名称。空格、大小写和标点可以规范化，但保留版本数字、日期、参数规模和思考版本。数字 `5.1` 与 `51` 不合并。编码代理只剥离已知工具外壳和明确推理档位；混合模型、未知后缀及冲突别名保持未知。缺失的 canonical 关联不会通过供应商包装名称猜出。

每次读取榜单都重新关联已保存的 catalog，因此榜单新增模型或 catalog 补充资料无需修改应用代码。无法确认身份或上游尚未收录时不补值；这条流水线不保证全模型、全字段覆盖。它不改变榜单分数、排名、厂商归属、投票量、国家规则及两种榜单时间。

Apple 共享 Kit 解码并离线保存资料和完整来源；Windows 引擎响应及 C# 模型保留同一份资料；小程序归一化、筛选和缓存保留资料。小程序使用用户文件目录中的临时文件写入后重命名，避免完整报价与图标超出单一 Storage 键容量，并兼容读取旧缓存。一次文件保存失败不覆盖上一份有效离线文件。

模型模式下点击名称进入详情：桌面使用可滚动窗口，手机和平板使用详情 sheet，小程序使用独立页面。名称旁的复制图标复制榜单原始名称，打开详情不会写剪贴板。公司模式原有行为保留。

详情展示资料、知识截止时间、上下文与输入输出限制、能力、模态、链接、权重及基准测试。各供应商报价独立折叠，标明美元 / 百万 tokens；阶梯门槛保持 token 数量。未匹配模型显示提示，仍可复制名称。未来公开字段放入其他资料。

扩展快照为 schemaVersion 2，attributes 保留经大小、深度和类型校验的公开字段；兼容旧快照，下一次同步主动升级。模型许可与数据集 MIT 许可分开展示。Windows 在点击时向本地引擎读取所选资料，避免完整目录重复进入每次榜单投影、超过进程通信大小限制。新界面需随新版客户端发布。
